## 1. Project Overview

**意識潮 My Tide** 是一件持續生長的數位互動文學作品，同時也是個人創作空間與全端技術實驗專案。

它不是傳統部落格、資訊入口網站，也不是以炫目的 3D 效果為目的的技術展示。

網站本身就是作品的一部分。

讀者可以在時間、文字、影像、記憶與互動空間之間探索。閱讀不一定局限於文字，也可能轉化為感知、移動或親身經歷。

**核心理念：內容決定閱讀體驗。**

## 2. Creative Philosophy

### 2.1 文字意在言外

文字不必說明所有事情。

作者希望透過時間、距離、空間、等待、沉默與互動，讓讀者感受到文字沒有直接表達的意義。

互動必須服務敘事，而不是為了展示技術。

### 2.2 網站本身是一件作品

意識潮不是先進入首頁，再選擇文章的傳統網站。

讀者進入網站的那一刻，就已經進入作品。

不同的內容可以改變網站的閱讀方式，甚至暫時改變原有的空間規則。

### 2.3 保留創作自由

不是每篇作品都需要動畫、3D 或互動。

一篇普通日記可以只是文字，一張照片可以安靜存在，一篇互動文學也可以擁有完全不同的介面與敘事方式。

不得要求所有作品套用相同的閱讀模板。

## 3. Product Inspiration

### Plurk — 時間序列

借鑑 Plurk 橫向時間軸的概念。

時間具有方向性，讀者可以向前或向後探索不同時期的記憶。

但意識潮不以社交動態或即時互動為主要目的。

### 無名小站 — 私人空間

借鑑早期個人網站的生活感與私人性。

可能包含：

- 網誌、日記與長篇文章
- 心情短句與日常碎念
- 相簿與影像記憶
- 訪客留言板
- 個人介紹與私人空間
- 內容分類、封存與閱讀權限

這些功能是產品發展方向，不代表全部已經完成或確定需要實作。

### 《蘇菲的世界》— 時間、距離與觀看

哲學小說《蘇菲的世界》中關於光年、宇宙與觀看過去的討論，是意識潮探索時間及空間敘事的思想啟發之一。

例如距離較遠的天體，其光線需要更長時間才會抵達觀察者。

這啟發了作者思考：距離與觀看位置，是否能夠改變讀者感知記憶的方式？

這是文學與哲學上的探索方向，不是已定義完成的 3D 功能需求。

## 4. Experience Architecture

### 4.1 時間之河 — The Timeline

意識潮保留橫向時間軸作為主要探索方式。

現有視覺特徵：

- 淡灰藍色系
- 大量留白
- 日期及時間資訊
- 細緻的波浪線
- 中央文章卡片
- 左右相鄰內容預覽

未來希望探索 Plurk 式的時間序感，以及可移動、改變視角與距離的空間。

不過，具體縮放方式、維度與互動規則仍在構思。

### 4.2 私人記憶空間

時間軸可以承載不同內容形式。

暫定內容概念：

| 類型 | 說明 |
|---|---|
| 潮記 | 日記、長篇文字 |
| 潮語 | 碎念、心情與短句 |
| 浮光 | 照片、相簿、影像 |
| 留聲 | 訪客留言及足跡 |
| 潮境 | 互動敘事及實驗文學 |

名稱為暫定工作名稱，可依創作方向調整。

### 4.3 Narrative Experience — 敘事體驗

讀者可能經歷三種狀態：

**Reading — 閱讀**

以文字或影像為中心，不強求互動。

**Perceiving — 感知**

透過移動、等待、距離、視角或聲音，感受到文字以外的意義。

**Experiencing — 經歷**

讀者的操作成為敘事的一部分，可能進入非線性、互動式或空間化的作品。

這三種狀態不是固定分類，同一篇作品也可以在不同狀態間轉換。

## 5. Technical Direction

### 5.1 技術組成

| 層級 | 技術 | 用途 |
|---|---|---|
| …… | …… | ……I 介接 |
| API | ASP.NET Core RESTful API | 業務邏輯、資料存取、API |
| Database | SQL Server | 結構化資料與持久化 |
| Deployment | Docker / IIS | 開發、測試與部署 |

目前網站已有 Docusaurus 基礎。

是否持續採用 Docusaurus、移至 Vite 或改用 Next.js，尚未決定，不應自行重構。

### 5.2 Web 與 API 分離

預計採用兩個獨立的 ASP.NET Core 應用程式：

- `MyTide.Web`
- `MyTide.Api`

初步資料流程：

Browser → React → MyTide.Web → MyTide.Api → SQL Server

目的是練習企業常見的 Web/API 分離架構、HttpClient、RESTful API、身分驗證、設定管理、IIS 與資料庫整合。

這是目標架構，不表示目前 Repository 已經具有上述全部專案。

### 5.3 Narrative Runtime

未來可以在 React 應用中建立敘事執行環境，用來承載不同作品的閱讀體驗。

可能使用：

- React Components
- MDX
- SVG
- Canvas
- Motion / Animation
- p5.js
- Three.js / React Three Fiber
- Web Audio

以上均為候選技術，應依實際作品需求選擇。

Three.js 並不是必要依賴。

## 6. Architecture Principles

- 創作需求優先於技術選型。
- 保留既有網站與作品成果，不隨意重寫。
- 前後端職責清楚，Web 與 API 可獨立部署。
- 優先使用可維護的模組化架構，不預設採用 Microservices。
- 內容模型應容許未來增加新的敘事形式。
- 敘事互動應保持可擴展，但避免提前建立過度抽象的框架。
- 讓讀者可以在意義上迷路，但在操作上仍能返回。

## 8. AI Agent Collaboration Guidelines

Claude Code、Codex CLI 參與此專案時，請遵守：

**Understand before implementing**

先閱讀背景文件、檢查 Repository，辨識既有實作與尚未完成的規劃。

**Do not over-engineer**

不要因為專案涉及互動文學，就自動引入 Three.js、狀態機、Microservices 或複雜的抽象設計。

**Preserve creative intent**

不要擅自將意識潮改造成 Dashboard、一般社群 Feed 或標準部落格首頁。

**Separate decisions from ideas**

區分已確立決策、候選技術與仍在構思的創作概念。

**Explain technical decisions**

涉及架構調整時，應說明：

- Do what：要完成什麼
- How to do：打算怎麼做
- Why：為什麼採用這個方案

**Do not implement speculative features**

未明確指定開發的功能，只能作為討論背景，不得直接實作。

## 9. Long-Term Vision

意識潮希望成為一個可以持續生長的私人數位文學世界。

它有時間順序，卻不一定只有線性時間。

它包含文字，卻不一定只能透過閱讀理解。

它可以有日常生活、相簿、留言與私人記憶，也能容納完全不同形式的互動敘事。

意識潮不是讓技術展示文學，而是讓技術成為文學可以……
