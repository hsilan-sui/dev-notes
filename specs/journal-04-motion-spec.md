# 04 · Motion Specification — The Journal

Motion philosophy (repeat from PRD, because every rule below derives from it): **design for contemplation, never for attention.** Slow. Elegant. Breathing. Calm. No bounce, no elastic, no "gamey" easing, nothing that resembles a notification or a loading spinner.

Pencil is a static tool — none of this could be animated inside the design file itself. The wording below (wave math, timings) is the actual specification the site owner reviewed and approved as a written **Motion Notes** annotation inside `design/blog-timeline.pen` (frame `Motion Notes — Wave Timeline`, id `qRAom`) plus the follow-up "same-day vertical" note (id `jLUQD`). This document expands those notes into implementation-precise numbers; it does not add new motion ideas beyond them.

---

## 1. Wave math (must be reproduced exactly — this is the Pencil source geometry)

The wave line and every day-node's vertical offset are generated by the same function. **Desktop constants:**

```
DAYS_VISIBLE_SAMPLE = 60      // Pencil's illustrative sample size; real DAYS = actual date-range length
SPACING   = 22   // px between consecutive day-nodes
PERIOD    = 340  // px, horizontal wavelength
AMP_MIN   = 6    // px, amplitude at the oldest (left) end of the visible track
AMP_MAX   = 16   // px, amplitude at the Current Moment (right) end
CENTER_Y  = 55   // px, vertical center line within a 110px-tall track
PHASE     = 0.6  // radians, static phase offset (do not randomize — must be reproducible/deterministic per page load, see §2 for what *does* vary over time)

trackWidth(days) = (days - 1) * SPACING + 20 + 110   // +20 left buffer, +110 right buffer (glow/companion clearance)

amplitude(x) = AMP_MIN + (AMP_MAX - AMP_MIN) * (x / trackWidth)   // linear ramp, grows toward the right/most-recent end

y(x) = CENTER_Y + amplitude(x) * sin( (2π * x / PERIOD) + PHASE )
```

**Mobile constants** (same formulas, different numbers): `SPACING=16, PERIOD=260, AMP_MIN=4, AMP_MAX=11, CENTER_Y=45` (within a 90px-tall track), `trackWidth = (days-1)*16 + 20 + 70`.

The rendered `<path>` is a polyline sampled every ~6px along `x` from `0` to `trackWidth`, i.e. `M x0 y(x0) L x1 y(x1) L x2 y(x2) ...`. At this amplitude/period this reads as a smooth curve without needing Bézier interpolation — do not add spline smoothing, it is not necessary and adds render cost.

Each day-node `i` (0-indexed, oldest → most recent) sits at `x = 20 + i * SPACING`, `y = y(x)` from the formula above.

## 2. "Wave — always breathing" (continuous idle motion)

> 波浪線持續、緩慢地位移（例如整條路徑隨時間做極小幅度的水平相位漂移），永不靜止、也永不誇張。振幅維持 8–16px，週期放慢，讓人感覺像水面或呼吸，而不是訊號波。

- The wave is **never fully static** on screen. Animate `PHASE` slowly over time (e.g. `phase(t) = 0.6 + 0.05 * sin(t / 9000)` — a barely-perceptible drift, period on the order of ~18 seconds for a full cycle) so the line is always gently alive, even when the user isn't touching it.
- This idle drift must be implemented with a method that costs near-zero main-thread work at rest (e.g. re-sampling the path via `requestAnimationFrame` at a throttled rate, or — preferable if feasible — animating via CSS custom properties / SVG `<animate>` so the browser's compositor does the work). It must **never** cause layout thrashing or visible jank; if a performant idle-drift cannot be shipped cheaply, it is acceptable to ship the wave **static** for v1 and flag this explicitly as a documented deferral in the final report (see `journal-09-task-breakdown.md`) — a cheap, honest static wave is better than a jank-y animated one that hurts perceived calm.
- **Amplitude note:** the site owner's verbal ask was "約 8–16px." The value actually built and approved in Pencil is **6–16px** (see §1). Ship 6–16px — it is the frozen, approved number; do not "round up" to 8 to match the earlier verbal ask.

## 3. "Current Moment — focus, not scale" (idle + on-change)

> 今天的節點大小與其他日子相同，不放大。聚焦感來自：靠近今天的振幅逐漸增加、節點不透明度逐漸提升、以及今天位置上一圈柔光（blur glow）。

- No size transition is ever applied to the Current Moment's node. If `currentMoment` changes (user navigates elsewhere and the concept of "most recent entry" doesn't change — this is about the wave *re-centering*, not the dot resizing), the glow and full-opacity treatment move to the new node's position via a plain opacity/position crossfade, duration **700ms**, `ease-out` (see §5 for the shared easing token). No node ever animates a `scale` transform.

## 4. Card — "emerging from time" (per-navigation transition)

> 切換文章時，卡片不是彈出或滑入，而是 Fade + 8–12px 上移同時發生，600–900ms，ease-out（無 bounce/elastic）。舊卡片先淡出、微下沉，新卡片接著淡入、微上浮。

Applies identically to horizontal (day-to-day) and vertical (same-day) navigation — both axes use the same transition, per the site owner's follow-up note; only the *trigger* differs, not the motion.

- **Outgoing card:** opacity `1 → 0`, translateY `0 → +8px` (sinks slightly), duration **600ms**, `ease-out`.
- **Incoming card:** opacity `0 → 1`, translateY `-8px → 0` (rises slightly), duration **700–900ms**, `ease-out`, starting with a small delay so it doesn't visually overlap-fight the outgoing card (recommended: start the incoming animation ~150–200ms after the outgoing one begins — a soft cross-fade, not a hard cut, and not a simultaneous 1:1 swap).
- Never use `translateY` greater than 12px. Never add `scale`, `rotate`, `blur`-in, or any spring/bounce curve. Respect `prefers-reduced-motion` — see `journal-05-accessibility-spec.md` §Reduced motion, which take priority over this section when that media query is active.

## 5. Timeline drag-release settle

> 水平拖曳時整條波浪跟著慣性緩緩滑動，停下來時波浪不會瞬間定住，而是像水面一樣多晃 1–2 個週期才慢慢平靜下來。

- On pointer-drag release (desktop/mouse/trackpad, not native touch scroll — see Interaction Spec §10 for the touch substitution), the scroll position continues with its released velocity, decaying (recommend a simple exponential decay, e.g. `velocity *= 0.94` per frame) until it drops below a small threshold, then stops. This alone gives the "water" feeling; an explicit secondary oscillation/rebound is optional polish, not required for v1 — do not spend implementation time hand-rolling a spring-physics bounce if the exponential-decay glide already feels calm. If in doubt, prefer the simpler implementation.
- This is the **one** place in the whole product where velocity-based physics is allowed. Nowhere else (card transitions, glow, focus states) should use spring/physics-based easing — they are all fixed-duration `ease-out` curves.

## 6. Motion tokens (name these exactly; consumed by Component Spec / Design Tokens)

```
--journal-motion-duration-card-out:   600ms
--journal-motion-duration-card-in:    800ms   /* midpoint of the 700–900ms range */
--journal-motion-duration-moment:     700ms
--journal-motion-ease:                cubic-bezier(0.22, 1, 0.36, 1)   /* a standard, non-elastic ease-out */
--journal-motion-translate-card:      8px      /* use 8, not 12 — the smaller end of the 8–12px range, reads calmer */
--journal-motion-wave-drift-period:   18000ms
--journal-motion-wave-drift-amplitude: 0.05    /* radians, added to PHASE */
```

No token in this product uses `ease-in`, `ease-in-out` with overshoot, `cubic-bezier` values whose curve exceeds `1.0` on either axis (that produces bounce/elastic), or any duration below `500ms` for a user-facing transition. Hover/focus micro-transitions (border-color, icon-color — Interaction Spec §8–9) may use a short `150–200ms` linear/ease transition; that exception exists only for those two low-drama color shifts, not for layout or opacity/translate motion.

## 7. What must NOT be built

Explicitly out per the site owner's own words — do not "improve" by adding any of these later without going back through design:

- Parallax on scroll.
- Any bounce/elastic/spring easing anywhere except the one exponential-decay drag-release glide (§5).
- Card entrance via `slide-in-from-right`/`translateX` (that reads as "switching articles," which this design explicitly rejects — see PRD §5).
- A pulsing/breathing *opacity* animation on the Current Moment glow (the glow is static; "breathing" belongs to the wave's phase drift only, §2).
- Skeleton loaders, shimmer effects, spinners — if content needs a moment to load, prefer a plain, motionless empty state over anything that reads as "loading UI."
