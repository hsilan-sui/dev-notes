【Interfaces】Interfaces 介面型別

🟧 開場白​

介面(Interfaces)，可以把物件的資料定義為型別，定義完之後資料就可以有條理地去做管理 !

🟦 TypeScript 常用型別​

0️⃣ 函式（Function）​

資訊
  • 在函式上有兩種定義：
    • 一種是函式陳述式
    • 一種是函式表達式

  • 函式陳述式(Function Declaration)

函式陳述式(Function Declaration)
function add(a: number, b: number): number {
  return a + b;
}

  • 函式表達式(Function Expression)

函式表達式(Function Expression)
let sum = function (x: number, y: number): number {
  return x + y;
};

  • 箭頭函式

箭頭函式
let sum = (x: number, y: number): number {
  return x + y;
};

  • 函式 型別註釋(Type Annotations)

函式 型別註釋(Type Annotations)
//這裡是函式型別註釋(Type Annotations)寫法 =>代表函式輸出會是number

let sum: (x: number, y: number)=>number = function (x: number, y: number): number {
  return x + y;
};
  • 但懂的型別推斷才不會把ts寫得越來越複雜 !

1️⃣ 如果函式沒有回傳值：void​

函式沒有回傳值：void
函式沒有回傳值：void

  console.log(message);
}

  • 圖片引用來自六角後端實戰班
物件-型別註釋寫法

let product: { //型別註釋寫法
  name: string,
  price: number,
  inStock: number
} = {

  inStock: 150

4️⃣ 列舉型別（Enum）​

  • JS是沒有這東西的，是TS才有

  • 圖片引用來自六角後端實戰班
列舉型別- 平台管理

//平台管理
enum Role {
  Admin, 
  Author,
  ReadOnlyUser
}

let user = {
  name: "Alice",
  role: Role.Admin
}

console.log(user)

//輸出
[LOG]: {
  "name": "Alice",
  "role": 0
}
  • 做一個更進階的列舉狀態練習
列舉型別- 定義任務狀態列舉

//定義一個任務列表
enum TaskStatus {
  Todo,  // 代辦事項
  InProgress, //進行中
  Done //已完成
}

//空的任務陣列 => 定義該任務為陣列型 別
let tasks: {name: string, status: TaskStatus }[] = []

//新增陣列
function createTask(name: string) {
  tasks.push({
    name: name,
    status: TaskStatus.Todo
  })
}

// 新增任務到任務列表
createTask("學習TS");
createTask("去超市購物");

//顯示任務

console.log(tasks);

6️⃣ 聯合型別（Union Types）​

聯合型別（Union Types）

let id: string | number;

id = "1234";
id = 1234;

let names: string | string[];
names = "Alice";
names = ["Alice", "Bob"];

function displayPrice(price: number | [number, number]) {
  if (typeof price === "number") {
    console.log(`價格：${price}`)
  } else {
    console.log(`價格範圍：${price[0]}~${price[1]}`)
  }
}

displayPrice(49.99)
displayPrice([33.55])

用於手動設定值的型別

型別斷言

🟦 介面型別​

圖書館範例
//interfaces
//my book  圖書館範例

let myBook = {
    isbn: "239981777",
    title: "JS全攻略",
    author: "TOM",
    year: 2009
}

//印出
function printBook(book: {isbn: string, title: string, author: string, year: number }) {
    console.log(`書名標題是：${book.title}`)
}

printBook(myBook);
  • 上面函式的參數塞太滿，不好閱讀，所以Interfaces型別是讓程式碼可讀性變高，統一在物件都做好介面型別，未來其他程式碼要載入該物件也是相當好管理

0️⃣ 重構圖書館範例，加入介面型別​

自訂Book介面型別

//宣告 Book 介面型別
interface Book {
    isbn: string,
    title: string,
    author: string,
    year: number  
}

let myBook: Book = {
    isbn: "239981777",
    title: "JS全攻略",
    author: "TOM",
    year: 2009
}

//印出 這裡參數集中在介面型別 所以這裡可讀性就變高了
function printBook(book: Book) {
    console.log(`書名標題是：${book.title}`)
}

printBook(myBook);

1️⃣ 將任務代辦清單加入介面型別​

將任務代辦清單加入介面型別

//介面型別
interface Task {
  name: string,
  status: TaskStatus
}

//定義一個任務列表
enum TaskStatus {
  Todo,  // 代辦事項
  InProgress, //進行中
  Done //已完成
}

//空的任務陣列 => 定義該任務為陣列型 別
let tasks: Task[] = []

//新增陣列
function createTask(name: string) {
  tasks.push({
    name: name,
    status: TaskStatus.Todo
  })
}

// 新增任務到任務列表
createTask("學習TS");
createTask("去超市購物");

//顯示任務

console.log(tasks);
