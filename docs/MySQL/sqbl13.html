本文參考：SQL Lesson 12: Order of execution of a Query

SQL Query Order of Execution：我寫 SELECT 在最前面，但它其實不是先執行

預估閱讀時間：約 8 分鐘

本篇觀念要點​

我平常寫 SQL 時，順序看起來是：

SELECT
FROM
JOIN
WHERE
GROUP BY
HAVING
ORDER BY
LIMIT

所以我很容易直覺認為：

SQL 就是從 SELECT 開始一路往下執行。

但我要分清楚兩件事情：

SQL 的書寫順序
≠
SQL 的邏輯執行順序

SQL 的邏輯執行順序，可以先記成：

FROM 和 JOIN
→ WHERE
→ GROUP BY
→ HAVING
→ SELECT
→ DISTINCT
→ ORDER BY
→ LIMIT 和 OFFSET

理解這個順序之後，我以前很多「為什麼 SQL 不能這樣寫」的問題就會比較合理。

例如：

  • 為什麼 WHERE 和 HAVING 不一樣
  • 為什麼 WHERE 常常不能直接使用 SELECT 的 Alias
  • 為什麼 ORDER BY 卻可以使用 Alias
  • 為什麼是 JOIN 完資料後才 GROUP BY
  • Aggregate Function 到底是在什麼資料上計算
學習主線

先取得資料 → JOIN 成我要工作的資料 → WHERE 篩 Row → GROUP BY 把 Row 分成 Group → HAVING 篩 Group → SELECT 計算與輸出結果 → DISTINCT 去重複 → ORDER BY 排序 → LIMIT 取最後需要的資料

為什麼我要理解 Query Execution Order

假設我看到：

SELECT
    m.Director,
    SUM(b.domestic_sales + b.international_sales) AS total_sales
FROM Movies AS m
INNER JOIN Boxoffice AS b
    ON b.Movie_id = m.Id
GROUP BY m.Director;

如果照程式碼從上往下看，我可能會以為：

先 SELECT
↓
再找 Movies
↓
再 JOIN Boxoffice
↓
最後 GROUP BY

但這不是我理解 SQL 資料流的方式。

我應該想：

先取得 Movies
↓
JOIN Boxoffice
↓
現在每一列有電影、導演和票房
↓
按照 Director 分組
↓
每個 Director 得到自己的電影 Group
↓
SUM 每一組的電影票房
↓
SELECT 最後輸出 Director 和總銷售

所以我要記：

SELECT 雖然寫在第一行，但在邏輯執行上其實很後面。

SQL Query 的邏輯執行順序

1. FROM 和 JOIN：先建立我要工作的資料

第一個階段不是 SELECT。

而是：

FROM ...
JOIN ...

我可以把它理解成：

先決定這次 Query 到底有哪些資料可以使用。

例如：

FROM Movies AS m
INNER JOIN Boxoffice AS b
    ON b.Movie_id = m.id

代表：

Movies
+
Boxoffice
↓
透過電影 Id 接起來
↓
得到新的 Working Set

這時候最重要的是問自己：

JOIN 完以後，一列現在代表什麼？

如果 JOIN 完是一部電影配上一筆 Boxoffice：

一列
=
一部電影
+
它的導演
+
它的票房資料

這會直接影響我後面怎麼 GROUP BY。

2. WHERE：先篩選原始 Row

有了 Working Set 之後才輪到：

WHERE

例如：

WHERE m.Year >= 2000

意思是：

JOIN 完的所有電影 Rows
↓
一列一列判斷 Year
↓
符合條件 → 留下
不符合條件 → 丟掉

所以我要把 WHERE 記成：

在分組以前，先篩選單筆 Row。

WHERE 和 HAVING 為什麼不一樣

我以前很容易只記：

WHERE 不能處理 Aggregate
HAVING 可以

但其實更重要的是它們所在的位置。

FROM 和 JOIN
↓
得到 Rows
↓
WHERE
↓
篩 Rows
↓
GROUP BY
↓
Rows 形成 Groups
↓
HAVING
↓
篩 Groups

所以：

WHERE​

我現在處理的是：

Row。

HAVING​

我現在處理的是：

Group。

這樣我就不用死背它們的差異。

3. GROUP BY：把 Row 變成 Group

例如：

GROUP BY m.Director

這一步本身不是在計算總銷售。

它只是說：

相同 Director 的電影 Rows 要被放在同一組。

例如原本：

John Lasseter → Toy Story
John Lasseter → A Bug's Life
John Lasseter → Toy Story 2
Andrew Stanton → Finding Nemo
Andrew Stanton → WALL-E

經過：

GROUP BY m.Director

我可以想成：

John Lasseter Group
├── Toy Story
├── A Bug's Life
└── Toy Story 2

Andrew Stanton Group
├── Finding Nemo
└── WALL-E

所以我前面學過的 Mental Model 還是一樣：

GROUP BY 回答的是：誰一組？

4. HAVING：Group 建好之後才篩選

例如：

GROUP BY m.Director
HAVING COUNT(*) >= 2

Group 已經先形成：

John Lasseter
→ 5 部電影

Andrew Stanton
→ 2 部電影

Brenda Chapman
→ 1 部電影

然後：

HAVING COUNT(*) >= 2

才做：

John Lasseter → 留下
Andrew Stanton → 留下
Brenda Chapman → 排除

所以：

HAVING 是在 Aggregate / Group 層級做篩選。

5. SELECT：現在才決定我要輸出什麼

到了這裡才真正處理：

SELECT

例如：

SELECT
    m.Director,
    SUM(b.domestic_sales + b.international_sales)

這時前面已經知道：

有哪些資料
↓
哪些 Row 留下
↓
哪些 Row 屬於同一個 Director Group

所以現在才能真正計算最後要輸出的結果。

6. DISTINCT：對 SELECT 結果去重複

例如：

SELECT DISTINCT Director
FROM Movies;

可以理解成：

FROM Movies
↓
SELECT Director
↓
得到 Director 結果
↓
DISTINCT
↓
移除重複值

7. ORDER BY：最後才排序

例如：

SELECT
    m.Director,
    SUM(b.domestic_sales + b.international_sales) AS total_sales
FROM Movies AS m
JOIN Boxoffice AS b
    ON b.Movie_id = m.id
GROUP BY m.Director
ORDER BY total_sales DESC;

到 ORDER BY 的時候：

SELECT
↓
total_sales 已經計算完成
↓
ORDER BY

所以這時通常可以使用：

total_sales

這個 Alias。

為什麼 WHERE 常常不能使用 SELECT Alias

例如：

SELECT
    domestic_sales + international_sales AS total_sales
FROM Boxoffice
WHERE total_sales > 500000000;

我可能會想：

我上面明明已經把它取名叫 total_sales 了。

但我要改成看執行順序：

FROM
↓
WHERE
↓
SELECT

執行 WHERE 的時候：

total_sales

這個 SELECT Alias 還沒有產生。

所以我要記：

SQL 寫在上面，不代表比較早執行。

8. LIMIT 和 OFFSET：最後再決定拿幾筆

例如：

ORDER BY total_sales DESC
LIMIT 3;

不是：

先抓 3 筆
↓
再排序

而是：

先完成結果
↓
ORDER BY 排序
↓
LIMIT
↓
拿排序後前三筆

SQL 的書寫順序和執行順序

我寫 SQL 時​

SELECT
FROM
JOIN
WHERE
GROUP BY
HAVING
ORDER BY
LIMIT

我理解資料怎麼流時​

FROM
JOIN
WHERE
GROUP BY
HAVING
SELECT
DISTINCT
ORDER BY
LIMIT

這兩個順序我要分開。

→ 一部電影

→ 一位 Director

一部電影
↓

↓

SUM(...)

↓
SUM
↓
一個 Director 的總銷售

GROUP BY m.Director

代表：

誰一組？

Director。

GROUP BY
→ 誰一組

Row Expression
→ 每一列先算什麼

Aggregate Function
→ 每一組再算什麼

執行階段這題發生什麼
FROM Movies先拿電影資料
JOIN Boxoffice補上每部電影的 Sales
JOIN 後粒度一列是一部電影和它的銷售
GROUP BY Director同一導演的電影放成一組
Domestic + International算一部電影自己的總銷售
SUM把同一導演所有電影加起來
SELECT輸出 Director 和總銷售
最後粒度一列是一位 Director

一句話記住

SQL 的 Query Execution Order 不只是要我背：

FROM
JOIN
WHERE
GROUP BY
HAVING
SELECT

真正重要的是，我可以沿著執行順序一直追蹤：

現在的一列代表什麼？

這題就是：

Movies
→ 一列是一部電影

JOIN Boxoffice
→ 一列是一部電影和它的 Sales

GROUP BY Director
→ 同一位 Director 的電影成為一組

Domestic + International
→ 每部電影先算自己的總銷售

SUM
→ 每組再加總所有電影

SELECT
→ 最後一列是一位 Director

從「一部電影」一步一步變成「一位導演的總銷售」。
