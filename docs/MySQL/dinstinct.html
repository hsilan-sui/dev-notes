【SQL DISTINCT】去除重複資料

預估閱讀時間：約 4 分鐘

本篇我要記住​

DISTINCT｜去除重複資料，用來讓 SELECT 的結果只保留不重複的值或組合。

SELECT DISTINCT column
FROM table;

我的核心記法：

DISTINCT 不是分組計算，而是「這個 SELECT 結果不要重複」。先SELECT 出來，再DISTINCT去重

1. 為什麼需要 DISTINCT​

假設有一張員工表：

Employees​

employee_idnamedepartmentcity
1AmyITTaipei
2BobITTaipei
3CindyHRTaoyuan
4DavidHRTaipei
5EricITTaoyuan
6FionaSalesTaipei
7GraceSalesTaipei
8HenryITTaipei

如果：

SELECT department
FROM Employees;

我會得到：

IT
IT
HR
HR
IT
Sales
Sales
IT

但如果需求只是：

公司「有哪些部門」？

我根本不需要看到重複的 IT。

所以使用：

SELECT DISTINCT department
FROM Employees;

結果：

department
IT
HR
Sales

2. DISTINCT 多個欄位​

這是我最需要記住的地方。

SELECT DISTINCT department, city
FROM Employees;

不是：

department 自己去重一次，city 自己去重一次。

而是：

department + city 整個組合不能重複。

例如：

departmentcity
ITTaipei
ITTaipei
HRTaoyuan
HRTaipei
ITTaoyuan
SalesTaipei

執行 DISTINCT 後：

departmentcity
ITTaipei
HRTaoyuan
HRTaipei
ITTaoyuan
SalesTaipei

因此寫法是：

SELECT DISTINCT department, city
FROM Employees;

而不是：

SELECT DISTINCT(department, city)
FROM Employees;

3. COUNT 搭配 DISTINCT​

如果需求變成：

公司總共有幾種不同的部門？

這次不只是把部門列出來，而是要「數有幾種」。

SELECT COUNT(DISTINCT department)
FROM Employees;

我的理解流程：

原始 department
↓
DISTINCT 去除重複
↓
IT
HR
Sales
↓
COUNT 計算數量
↓
3

4. DISTINCT vs GROUP BY​

這兩個有時候看起來會產生類似結果，但我的目的不同。

DISTINCT​

問題是：

「有哪些不同的東西？」

例如：

SELECT DISTINCT department
FROM Employees;

我要的是：

IT
HR
Sales

GROUP BY​

問題通常是：

「每一組各自怎麼樣？」

例如：

SELECT department, COUNT(*) AS employee_count
FROM Employees
GROUP BY department;

我要的是：

departmentemployee_count
IT4
HR2
Sales2

所以我的判斷方式：

我想知道使用
有哪些不同的部門？DISTINCT
有哪些不同的城市？DISTINCT
有哪些不同的部門＋城市組合？DISTINCT
有幾種不同部門？COUNT DISTINCT
每個部門有幾個人？GROUP BY + COUNT
每個部門的薪資總和？GROUP BY + SUM

關鍵記憶​

SELECT DISTINCT department

department 不重複。

SELECT DISTINCT department, city

department + city 的組合不重複。

COUNT(DISTINCT department)

計算有幾種不同的 department。

而：

GROUP BY department

是把資料依照 department 分組，準備進行每組的聚合計算。

一句話記住​

DISTINCT = 不要重複。

GROUP BY = 我要以誰為一組，然後對每組做事情。
