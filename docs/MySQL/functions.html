【SQL Functions】我到底是在算「一列」還是「一群資料」？

我學到 COUNT()、SUM()、CONCAT() 的時候，其實每一個語法單獨看，我都知道它在幹嘛。

例如：

COUNT()
SUM()
AVG()
CONCAT()

我知道：

  • COUNT() 是數數量
  • SUM() 是加總
  • AVG() 是平均
  • CONCAT() 是把字串接起來

但真的開始加上group by和其他一起來解題，我還是會卡住。

所以我的問題其實不是：

「我不知道 COUNT 是什麼。」

而是：

「COUNT 現在到底在數哪些資料？」

以及：

「這個 Function 是對每一個資料列做事情，還是把很多列一起拿來算？」

再往下一層，其實是：

「我現在看到的一列代表什麼？最後又希望一列代表什麼？」

這才是我要真正搞懂的東西。

1. 我先重新理解 Function

Function 先不要想得太複雜。

我可以把它理解成：

給它資料
   ↓
Function 做事情
   ↓
得到結果

例如：

SELECT CONCAT(first_name, ' ', last_name)
FROM employees;

CONCAT() 收到：

first_name
空格
last_name

例如某一列是：

John
Smith

那這一列執行：

John + 空格 + Smith
        ↓
     John Smith

所以：

CONCAT(first_name, ' ', last_name)

本質就是：

Input
  ↓
CONCAT
  ↓
Output

到這裡其實跟我以前理解 JavaScript、Python 的 Function 沒有差很多。

但 SQL 有一個我要特別注意的地方：

SQL Function 是在 Table 的資料上工作。

所以我不能只問：

這個 Function 做什麼？

我還要問：

它現在是對「一列」做，還是對「很多列」做？

這就會分成兩種很重要的 Function：

Scalar Function
→ 每一列自己算自己的

Aggregate Function
→ 很多列一起算出一個結果

2. Scalar Function(純量函式/標量函式)：我把它想成「每一列自己處理」

假設現在有：

emp_nofirst_namelast_name
101JohnSmith
102AmyChen
103TomLee

我執行：

SELECT
    emp_no,
    CONCAT(first_name, ' ', last_name) AS 全名
FROM employees;

以前我可能只會記：

CONCAT() 可以串接字串。

但我現在要多看一層。

SQL 實際上是在做：

先取～employees員工資料表;

選擇查詢員工編號(emp_no)和 全名(標量函式concat()只是把每列各自的資料columns 組成字串來看)

第 1 列
John + Smith
↓
John Smith


第 2 列
Amy + Chen
↓
Amy Chen


第 3 列
Tom + Lee
↓
Tom Lee

也就是：

Row 1 → CONCAT → Result 1
Row 2 → CONCAT → Result 2
Row 3 → CONCAT → Result 3

最後：

emp_nofull_name
101John Smith
102Amy Chen
103Tom Lee

這裡我要注意：

原本有 3 個 Employee rows，做完 CONCAT 之後還是 3 個 Employee rows。

3 rows
  ↓
CONCAT
  ↓
3 rows
資訊

CONCAT() 沒有把 John、Amy、Tom 合成一筆資料。

它只是：

John 處理 John 的。 Amy 處理 Amy 的。 Tom 處理 Tom 的。

所以我可以把 Scalar Function標量函式 記成：

每一列自己算自己的。

3. Scalar Function 最重要的地方：它沒有改變「一列是誰」

這句我要特別記。

原始 employees：

一列 = 一位 Employee

做完：

CONCAT(first_name, ' ', last_name)

之後：

一列 = 還是一位 Employee

只是原本：

John | Smith

現在多算出：

John Smith

所以 Scalar Function 通常是在：

改變這一列裡面的值，而不是把很多列收起來。

4. 再用幾個例子確認 Scalar

例如：

SELECT UPPER(first_name)
FROM employees;

資料：

John
Amy
Tom

實際概念：

John → UPPER → JOHN
Amy  → UPPER → AMY
Tom  → UPPER → TOM

還是三列。

如果是：

SELECT LENGTH(first_name)
FROM employees;

則是：

John → LENGTH → 4
Amy  → LENGTH → 3
Tom  → LENGTH → 3

還是：

一個 Employee
↓
Function
↓
這個 Employee 的計算結果

所以我以後看到：

CONCAT()
UPPER()
LOWER()
LENGTH()

先想到：

這些 Function 通常是在每一列各自執行。

5. Aggregate Function 完全不一樣

現在換一張薪資表：

emp_nosalary
101100
102200
10350
10450

如果我寫：

SELECT SUM(salary)
FROM salaries;

這時候不是：

100 → 一個結果
200 → 一個結果
50  → 一個結果
50  → 一個結果

而是：

100
200
 50
 50
───
 ↓
SUM
 ↓
400

原本：

4 rows

最後：

1 value

這就是 Aggregate 聚合函式。

6. 我可以把 Aggregate 理解成「把一群資料收起來算」

常見的： 

COUNT()
SUM()
AVG()
MAX()
MIN()

例如：

salary

100
200
50
50

COUNT​

COUNT(*)

我是在問：

這一群資料有幾列？

答案：

4

SUM​

SUM(salary)

我是在問：

這一群 salary 全部加起來是多少？

答案：

400

AVG​

AVG(salary)

我是在問：

這一群 salary 的平均是多少？

答案：

100

MAX​

MAX(salary)

我是在問：

這一群 salary 最大的是多少？

答案：

200

MIN​

MIN(salary)

我是在問：

這一群 salary 最小的是多少？

答案：

所以不管是哪一個 Aggregate Function，核心都是：

很多 rows
   ↓
把它們當成一群
   ↓
Aggregate
   ↓
一個 Summary

7. 所以 Scalar 跟 Aggregate，我真正要分的是這件事

我不要只背：

Scalar 是什麼、Aggregate 是什麼。

我要直接看資料。

Scalar​

Row 1 → Result 1
Row 2 → Result 2
Row 3 → Result 3

也就是：

每一列自己處理。

Aggregate​

Row 1
Row 2
Row 3
  ↓
一起算
  ↓
Result

也就是：

很多列一起處理。

每個 Department 一列。

10. 我現在怎麼理解 GROUP BY？

我以前很容易把 GROUP BY 想成：

「這題好像有 COUNT，所以我要 GROUP BY 一些欄位。」

這樣很容易亂掉。

我現在應該想：

GROUP BY 是在決定「哪些 rows 要被視為同一組」。

例如：

GROUP BY department

其實就是把：

Amy   IT
Tom   IT
John  HR
Mary  HR
Bob   HR

整理成：

IT 這一組
├── Amy
└── Tom


HR 這一組
├── John
├── Mary
└── Bob

接著 COUNT() 才進來。

IT Group
├── Amy
└── Tom
     ↓
   COUNT
     ↓
     2

以及：

HR Group
├── John
├── Mary
└── Bob
     ↓
   COUNT
     ↓
     3

所以我現在可以把兩件事拆開：

GROUP BY：誰一組？

Aggregate Function：每一組要算什麼？

這兩個問題不是同一個問題。

11. Aggregate 不是永遠「整張表變一列」

這裡是我一定要修正的地方。

如果沒有：

GROUP BY

那：

整張 Table
↓
可以視為一整組
↓
COUNT
↓
一個答案

但如果：

GROUP BY department

就會變成：

整張 Table
     ↓
按照 department 分組
     ↓
IT Group       HR Group
   ↓              ↓
 COUNT          COUNT
   ↓              ↓
   2              3

所以更精確的理解不是：

Aggregate = 整張表變成一列。

而是：

Aggregate Function 會對「目前的一組 rows」算出一個結果。

有沒有 GROUP BY，會決定「一組」到底是什麼。

誰一組
↓
GROUP BY

每組算什麼
↓
COUNT SUM AVG

哪些組留下
↓
HAVING

我這篇真正要帶走的一句話

SQL 解題時，我不要先找語法，我要先追蹤「一列代表什麼」。

Scalar Function：

一列
↓
處理
↓
還是一列

Aggregate Function：

很多列
↓
一起計算
↓
一個結果

GROUP BY + Aggregate：

很多列
↓
按照「我希望誰一列」來分組
↓
每組做 Aggregate
↓
每組得到一列

所以如果下次我又卡在 GROUP BY，先不要亂加欄位。

回來問自己：

「題目最後到底要誰一列？」
